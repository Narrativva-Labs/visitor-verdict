# Verdict model and integration boundary

A claimed identity is independent of evidence. A UA token is spoofable. A valid signature proves possession of a key published at a trusted operator endpoint over the covered components. A published-IP match is weaker evidence of a network range, usually gated by a relevant UA token. Neither result proves humanity, user intent, consent, purchase approval or authorization.

A reusable createVerifier validates and snapshots trusted configuration once and owns its cache. Each request supplies a host that must normalize to an allowed external authority. Unknown/internal/context failures are indeterminate. An unsigned request can never be signature_invalid. The configured authority supplies the signature base; raw Host values are not guessed or compared as alternative candidates. nginx adapters need `proxy_set_header Host $host;`; Caddy normally preserves Host, but deployed configuration must be checked. Do not trust client-controlled forwarded headers or unauthenticated sGTM envelopes.

Signed request targets preserve raw path, percent escapes and dot segments. No WHATWG path normalization is applied. Only SP/HTAB is removed from field edges; ordinary obs-text is part of signed data. A linear SF guard prevents duplicate overwrite, Decimal timestamp type loss, misclassification of token colons and quadratic whitespace processing. Aggregation limits apply before parsing. Unsupported components are never skipped; content-digest cannot establish body integrity without body bytes.

Each label is evaluated separately. A valid trusted signature wins, then definitive invalid, then indeterminate. IP evidence is separate and cannot hide a presented invalid signature. Dictionary members with unsupported parameters are untrusted at that label, not a reason to discard a valid peer. Unknown identities never initiate network access. Keys accept both RFC thumbprint and operator kid aliases; the verdict reports which matched. Mixed directories skip unsupported keys but reject structural ambiguity and private keys.

Retention for public verification material is independent of HTTP cache semantics: 300 seconds minimum, 24 hours maximum, with JWK nbf/exp checked at each use. This intentionally retains public no-store directories long enough for reliable verification, without retaining request headers/IPs/signatures/nonces. Refreshes are single-flight; cooldown follows failure or forced unknown-key refresh only. Compiled IP BlockLists are reused. Feed fetches run in parallel; the overall deadline and per-operation timeboxes bound latency. A request deadline does not abort a refresh shared by another request.

The captured OpenAI signatures cover authority, method and Signature-Agent. They do not bind path, query, body or the initiating person. Default analytics mode allows replay and stores no nonce. Opt-in NonceStore is a caller-owned atomic replay/privacy choice with bounded calls; it does not authorize actions. Network trust rests on exact configured HTTPS endpoints, not an unauthenticated directory proof. Endpoint compromise/DNS/egress policy remains a deployment responsibility.

Own-browser agents can share a person's normal browser, cookies, UA and IP without signatures. No-signature/none is not human. This verifier does not detect those agents. Anthropic Claude-Agent is documented through IP+UA/SAIL rather than an assumed WBA identity; SAIL stays disabled until its live schema is confirmed. Other Claude tokens may use bots.json. Google signing is partial/experimental; generated-key tests prove syntax, not a real signed Google session. Google-CloudVertexBot uses common-crawlers ranges, not generic user-controlled fetcher networks. DuckDuckGo/Browserbase/Manus have live directory fixtures but no captured request identity; their origin identities remain provisional, with verifiedByCapture=false. The README operator table records this distinction.

This package supplies analytics evidence separately from browser traffic_class. It does not verify a human, consent, abuse policy, robots compliance, delegated rights, payload integrity, authorization to buy, or payment authority. Applications still enforce their normal authorization and conversion policy. Services receiving original-request context must authenticate that envelope; their own HTTP request cannot reconstruct the original browser signature.
