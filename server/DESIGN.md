# Verdict model and integration boundary

The library labels traffic and does not itself withhold anything. Conversion policy belongs to the integrator. A claimed identity is independent of evidence. A UA token is spoofable. A valid signature proves possession of a key published at a trusted operator endpoint over the covered components. A published-IP match is weaker evidence of a network range, usually gated by a relevant UA token. Neither result proves humanity, user intent, consent, purchase approval or authorization.

A reusable createVerifier validates and snapshots trusted configuration once and owns its cache. Each request supplies a host that must normalize to an allowed external authority. Unknown/internal/context failures are indeterminate. An unsigned request can never be signature_invalid. The configured authority supplies the signature base; raw Host values are not guessed or compared as alternative candidates. nginx adapters need `proxy_set_header Host $host;`; Caddy normally preserves Host, but deployed configuration must be checked. Do not trust client-controlled forwarded headers or unauthenticated sGTM envelopes.

Target syntax is validated only for covered target components, so an uncovered query ending in % or OPTIONS \* cannot change the outcome. Signed request targets preserve raw path, percent escapes and dot segments, including origin-form //path; absolute HTTPS scheme/authority and empty paths are normalized. No WHATWG path normalization is applied. Only SP/HTAB is removed from field edges; raw header values represent Latin-1 octets. The signature base must be ASCII: plain covered obs-text is rejected, while ;bs wraps each occurrence from its original Latin-1 bytes. Unicode above 255 is rejected rather than silently UTF-8 re-encoded. A linear SF guard prevents duplicate overwrite, Decimal timestamp type loss, misclassification of token colons and quadratic whitespace processing. Aggregation limits apply before parsing. Unsupported components are never skipped; content-digest cannot establish body integrity without body bytes.

Each label is evaluated separately. A valid trusted signature wins, then definitive invalid, then indeterminate. Other/absent tags are ignored_non_wba per label and cannot suppress IP matches or dominate WBA peers. IP evidence is separate and cannot hide a presented invalid WBA signature. Relevant feed failures without a match return none/ip_evidence_unavailable. All parameterized dictionary members (including either type=directory form, forbidden by protocol-01 §5.2.1) are untrusted at that label, not a reason to discard a valid peer. Unknown WBA identities never initiate network access; identity claims tied only to ignored non-WBA signatures do not prevent independent IP checks. Keys accept both RFC thumbprint and operator kid aliases; the verdict reports which matched. Mixed directories skip unsupported keys but reject structural ambiguity and private keys.

Retention for public verification material is independent of HTTP cache semantics: 300 seconds minimum, 24 hours maximum, with JWK nbf/exp checked at each use. This intentionally retains public no-store directories long enough for reliable verification, without retaining request headers/IPs/signatures/nonces. Fresh cached data takes precedence over a separate forced-refresh flight; ordinary/forced refreshes are single-flight independently; cooldown follows failure or forced unknown-key refresh only. Compiled IP BlockLists are reused. Feed fetches run in parallel; the timer starts before work, and per-operation timeboxes bound waiting. The overall deadline is best-effort over bounded synchronous work (method 32, host 2048, target 65536 and clientIp 64 characters). A request deadline does not abort a refresh shared by another request.

The captured OpenAI signatures cover authority, method and Signature-Agent. They do not bind path, query, body or the initiating person. Default analytics mode allows replay and stores no nonce. Opt-in NonceStore is a caller-owned atomic replay/privacy choice with bounded calls; it does not authorize actions. Network trust rests on exact configured HTTPS endpoints, not an unauthenticated directory proof. Endpoint compromise/DNS/egress policy remains a deployment responsibility.

Own-browser agents can share a person's normal browser, cookies, UA and IP without signatures. No-signature/none is not human. This verifier does not detect those agents. Anthropic Claude-Agent is documented through IP+UA/SAIL rather than an assumed WBA identity; a strict parser now supports the supplied live SAIL schema and resolves Claude-Agent service ranges; expires_after supplies the bounded retention TTL. Other Claude tokens may use bots.json. Google signing is partial/experimental; generated-key tests prove syntax, not a real signed Google session. Google-CloudVertexBot uses common-crawlers ranges, not generic user-controlled fetcher networks. DuckDuckGo/Browserbase/Manus have live directory fixtures but no captured request identity; their origin identities remain provisional, with verifiedByCapture=false. The README operator table records this distinction.

This package supplies analytics evidence separately from browser traffic_class. It does not verify a human, consent, abuse policy, robots compliance, delegated rights, payload integrity, authorization to buy, or payment authority. Applications still enforce their normal authorization and conversion policy. Services receiving original-request context must authenticate that envelope; their own HTTP request cannot reconstruct the original browser signature.

Registry entries may declare explicit server-only UA tokens, currently bingbot, while browser defaults remain an unchanged subset. Applebot and MistralAI-User also have documented JSON IP feeds. A collector normally uses its fixed configured host; Fastify trustProxy can make req.host depend on X-Forwarded-Host. Aggregate reason counters make context/feed faults visible without retaining request data. npm installation of this subfolder package uses an npm pack tarball, not a repository-root git dependency.
